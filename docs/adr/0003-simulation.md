# ADR 0003 — 시뮬레이션 코어

- 상태: 수용
- 날짜: 2026-11-17
- 개정: 2026-11-17. 코어의 언어를 Rust로 바꾼다. [ADR 0001](0001-tech-stack.md).

## 결정

코어는 Rust 함수다. 입력은 상태와 시드와 플레이어 행동이고, 출력은 다음 상태다. 크레이트는 `crates/sim-core`다. 웹 개발 빌드는 그 크레이트의 wasm을 부르고, Tauri는 같은 함수를 커맨드로 부른다.

React는 반환된 페이지를 그린다. MapLibre는 좌표를 그린다. 둘 다 규칙을 소유하지 않는다. `src/sim`에는 식을 두지 않는다. 배수를 천분율 정수로 넘기는 경계와 wasm 로더만 둔다.

시간을 진행하는 주체는 한 스케줄러다. 분기 마감은 그 스케줄러가 회사 하나의 마감을 부를 때 일어난다. 화면의 애니메이션이 회계를 진행시키지 않는다. 화면 밖 회사는 틱하지 않는다. 예산은 ADR 0001에 있다. 회사 하나의 마감은 1ms 미만, 화면에 있는 틱은 8ms 미만이다.

에이전트는 처음에는 스케줄러가 소유한 데이터와 메시지다. 엔티티가 함수 경계를 넘으면 ECS를 검토한다. 후보를 고를 때는 ADR 0001을 다시 연다. 시뮬을 TypeScript 힙으로 되돌리는 선택은 그 검토에 넣지 않는다.

가격을 만드는 함수는 이벤트가 호출한다. 분기 마감은 모델 배수만 갱신한다.

## 이유

재현과 테스트가 회계의 안전장치다. 렌더 프레임에 돈을 묶으면 기기 속도에 따라 분기가 달라진다. GC 정지와 입력 프레임을 같은 스레드에 두면 저사양 기기에서 예산이 먼저 깨진다.

회사 40곳과 에이전트 수십 명에게 ECS는 아직 크다. 경계만 시스템처럼 나눈다. 소싱, 회계, 코버넌트, 평판, 이벤트.

## 결과

`enterprise_value`와 `equity_value`가 그 경계의 첫 함수다. EBITDA와 천분율 배수로 기업가치를 만들고, 순차입금을 빼 지분가치를 만든다. 테스트는 `cargo test -p sim-core`다. LBO 스케줄과 워터폴은 스펙에 있고 코드에는 아직 없다.

## 개정 2026-11-19

코어가 세계 전체를 갖는다. `World`가 상태이고, `World::apply(Command)`만 상태를 바꾼다. 밖으로 나가는 것은 메시지와, 플레이어가 볼 수 있는 것만 담은 `view`다. 틱은 분기가 아니라 월이다.

- 회사는 화면에 있든 없든 매달 3제표를 닫는다. 250개에 1ms가 안 걸려 “화면 밖 회사는 틱하지 않는다”는 조건을 지킬 이유가 없어졌다.
- 돈과 비율은 전부 정수다. 부동소수는 IRR 계산에만 쓰고, 그 결과는 표시와 IC의 한 문턱에만 쓰인다.
- 난수는 SplitMix64 하나다. 상태가 세이브에 들어가 불러온 게임이 같은 길을 간다.
- 경계는 JSON 문자열이다. 커맨드와 뷰가 `serde`로 오간다. wasm과 Tauri가 같은 문자열을 쓴다.
- 안개는 코어가 건다. 세이브에는 모든 숫자가 있고, 뷰가 걸러 준다. 화면은 못 본 숫자를 받지 않는다.
