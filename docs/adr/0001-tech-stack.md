# ADR 0001 — 클라이언트와 언어

- 상태: 수용
- 날짜: 2026-11-17

## 결정

시뮬레이션과 화면은 TypeScript로 둔다. 화면은 Vite와 React다. 지도는 MapLibre GL JS다. 데스크톱과 모바일의 껍질은 Tauri 2다. 콘텐츠 파이프라인의 생성기는 Python 표준 라이브러리다. 런타임 저장은 SQLite이고, 개발 중 샘플은 JSON이다.

이 커밋에서 실행되는 것은 Vite 앱이다. `src-tauri` 프로젝트는 아직 생성하지 않았다. 껍질은 시스템 WebKit과 Rust 빌드가 갖춰진 뒤 `npm create tauri-app`에 해당하는 Tauri 2 절차로 같은 프론트엔드를 감싼다. 저장소의 Rustc는 1.83이었다. 빌드 의존성까지 이 부트스트랩에서 맞추지는 않았다.

## 이유

게임의 어려운 화면은 조밀한 한글 문서다. 3제표, IC 메모, 코버넌트, 계약 조건. React와 CSS가 그 조판을 맡고, 한글 글꼴은 Pretendard 또는 Noto를 고지 조건에 맞춰 나중에 넣는다.

지도는 제품의 기둥이다. MapLibre는 오프라인 벡터 타일(PMTiles)을 받을 수 있고, 사업체 이름 레이어를 뺄 수 있다. 빈 스타일로도 먼저 붙일 수 있다. 헬로 월드가 그 상태다.

돈과 항등식은 Vitest로 고정한다. `src/sim`은 DOM을 모른다.

Tauri 2는 2024-10-02에 안정판이 되었고, 데스크톱과 iOS, Android를 한 UI로 패키징한다. 라이선스는 MIT와 Apache-2.0이다. 서버가 필요 없다. 모바일 플러그인은 데스크톱보다 덜 갖춰져 있다는 점을 2.0 발표문이 밝힌다. v1의 플레이 검증은 데스크톱에서 하고, 같은 UI를 모바일로 옮긴다. 막히면 Capacitor가 같은 Vite 앱의 대체 껍질이다.

생성기를 Python으로 둔 이유는 런타임과 분리된 오프라인 파이프이기 때문이다. 표준 라이브러리의 `random`과 `sqlite3`만으로 재현된다. 통계 적합이 실제로 시작되면 그 스크립트만 의존성을 따로 가진다. 게임 빌드는 그 의존성을 품지 않는다.

## 같이 본 것

**Godot 4.** MIT. 데스크톱과 모바일을 한 프로젝트에서 내보내고, 카드와 핀의 손맛에 강하다. 3제표와 한글 메모, 지리 투영을 엔진 안에서 다시 만드는 비용이 이 게임에서는 더 크다. 첫 지도와 카드 프로토타입이 장소가 아니라 표만 같으면 이 결정을 다시 연다.

**Unity.** 런타임 피은 2024-09-12에 철회되었다. Personal은 직전 12개월 매출과 조달이 20만 달러 이하, Pro는 2026년 가격표 기준 시트당 연 2,310달러 또는 월 210달러다. 엔진의 수출 경험은 넓다. 한글 문서 UI와 오프라인 벡터 지도는 웹 스택이 더 직접적이다.

**Bevy.** ECS와 결정적 시뮬에 가장 잘 맞다. 조밀한 재무 UI와 모바일 제품화는 아직 리스크다. 에이전트가 늘면 런타임은 bitECS를 먼저 보고, 연구 모형은 Python Mesa로 돌린다.

**PixiJS와 Phaser.** 2D에 강하다. v1의 핀과 카드는 MapLibre 마커와 HTML이다. 일러스트 핀이 DOM으로 부족해지면 Pixi 레이어를 맵 위에 얹는다. 그 전까지 의존성으로 넣지 않는다.

## 결과

- `src/sim`, `src/data`, `src/ui`가 경계다.
- 릴리스 빌드의 네트워크 호출은 없다. 지도 타일도 로컬 파일이다.
- 돈은 백만 원 정수다.
