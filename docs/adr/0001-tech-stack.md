# ADR 0001 — 클라이언트와 언어

- 상태: 수용
- 날짜: 2026-11-17
- 개정: 2026-11-17. 시뮬레이션과 데이터 접근을 Rust로 옮긴다. 화면만 TypeScript로 남긴다.

## 결정

화면은 TypeScript, Vite, React다. 지도는 MapLibre GL JS다. 돈, 분기 마감, 에이전트 규칙, 콘텐츠 조회는 Rust다.

시뮬레이션 크레이트 `crates/sim-core`는 두 곳으로 컴파일한다.

- 네이티브. Tauri 2 커맨드가 호출한다. 커맨드 함수는 `crates/app-commands`에 있고, 껍질은 `src-tauri`다.
- `wasm32-unknown-unknown`. 웹 개발 빌드가 같은 함수를 부른다. 화면은 식을 다시 짜지 않는다.

콘텐츠는 SQLite다. 표는 인덱스를 가지고, 화면은 `LIMIT`과 `OFFSET`으로 한 페이지만 읽는다. 기본 페이지는 20장이다. 요청이 더 커도 50장을 넘기지 않는다. 목록과 지도가 보는 행은 최신 분기의 카드다. EBITDA, 배수(천분율 정수), 부채, 현금은 그 행에 미리 계산해 둔다. 분기 이력은 회사를 열 때 그 회사만 읽는다. 전체 JSON을 JS 힙에 올리지 않는다.

`rusqlite`는 wasm으로 컴파일되지 않는다. 웹 개발 빌드는 그래서 DB 파일을 통째로 열지 않고, 생성기가 써 둔 카드 페이지 한 장(`public/sample-page.json`)을 가져온다. Tauri 빌드는 `content-db`가 SQLite를 연다. 생성기의 전체 이력 JSON과 `content.sqlite`는 개발 산출물이고 게임 번들에 들어가지 않는다.

돈은 `i64` 백만 원이다. 배수는 천분율 정수다. 7200은 7.200배다. 반올림은 0에서 멀어지는 반올림이다. 양수 예시는 이전 `Math.round`와 같다. 2549 × 7.2 = 18353.

이 환경의 rustc는 1.83.0이다. `cargo test -p sim-core -p content-db -p app-commands`는 여기서 통과했다. `src-tauri`는 Tauri 2.1.0(그 태그의 rust-version은 1.77.2)에 고정한 별도 워크스페이스다. 최신 Tauri 2.12의 워크스페이스 rust-version은 1.90이라 이 툴체인과 맞지 않는다. 이 이미지에는 WebKit 개발 파일이 없어 `src-tauri`는 링크하지 않았다. 웹 헬로 월드는 wasm 경로로 값을 계산한다.

생성기는 Python 표준 라이브러리다. 게임 빌드는 그 의존성을 품지 않는다.

## 성능 예산

저사양 Android는 메모리 4GB, 2022년 전후의 SoC를 기준으로 한다. 숫자는 출시 전에 그 기기에서 다시 잰다. 데스크톱 디버그 빌드의 통과는 이 예산을 충족했다는 뜻이 아니다.

| 항목 | 예산 |
| --- | --- |
| 콜드 스타트, 첫 지도 페인트 | 3초 미만 |
| 콜드 스타트, 입력을 받는 시점 | 5초 미만 |
| 첫 페이지 이후 JS 힙 | 80MB 미만 |
| 보이는 카드 한 페이지의 Rust 작업 집합 | 20MB 미만 |
| 프로세스, 보이는 타일 포함 | 350MB 미만 |
| 화면에 있는 시뮬 한 틱 | 8ms 미만. 120Hz 프레임 안에 남기기 위한 상한 |
| 회사 하나의 분기 마감 | 1ms 미만 |
| v1 북 40곳의 마감 | 16ms 미만. 화면 밖 회사는 틱하지 않는다 |
| 카드 조회 | 요청한 페이지만. 기본 20장, 상한 50장. 이력 전체를 돌려주지 않는다 |

## 벤치 계획

1. `content-db` 테스트가 카드 1,000장을 넣고 20장을 읽는다. 디버그 빌드에서 그 읽기는 500ms 안에 끝나야 한다. 이것은 연기가 새는지 보는 상한이다. 8ms 틱의 증거가 아니다.
2. 분기 마감과 틱이 코드에 들어오면 Criterion으로 1ms, 8ms 예산을 잰다. 릴리스 프로파일, 데스크톱, 그리고 v1 전에 저사양 Android에서 한 번씩이다.
3. `npm run build` 산출물의 JS에 전체 픽스처의 계정 필드(`retained_earnings` 같은 이력)가 없어야 한다. 카드 페이지는 `dist/sample-page.json` 한 장이다.
4. 메모리 예산은 대상 기기에서 Android Studio 프로파일러 또는 `adb shell dumpsys meminfo`로 확인한다. 그 측정이 있기 전에 예산을 달성했다고 쓰지 않는다.

## Rust를 고른 이유

**TypeScript만으로 시뮬과 DB를 두는 경우.** 화면과 회계가 같은 힙과 같은 스레드를 쓴다. 분기 이력이 커지면 시작 시간에 그대로 더해지고, GC 정지가 입력 프레임에 섞인다. 조판은 React가 잘한다. 장부와 조회는 그 힙 밖에 둔다.

**C#과 Unity.** 렌더와 모바일 수출은 넓다. 3제표와 MapLibre 지도를 살리려면 클라이언트가 둘로 갈라지거나, 화면까지 엔진 안으로 들어가 웹 개발 루프를 잃는다. Personal 한도는 직전 12개월 매출과 조달 20만 달러다. 그 선을 넘으면 시트가 다시 돈이 된다. 회계 코어에 그 런타임이 필요하지 않다.

**Godot, GDScript.** 씬과 손맛에는 짧다. GC와 인터프리터 틱은 프레임 예산(8ms) 안에 두기 어렵다. Godot C#으로 옮기면 시뮬이 그 렌더러에 묶이고, Tauri 커맨드와 wasm이 같은 크레이트가 되지 않는다. 지도와 카드가 대시보드처럼 느껴지면 렌더 레이어를 다시 연다. 그 경우에도 회계는 Rust에 둔다. [ADR 0004](0004-motion.md).

**Rust.** GC가 없다. 돈은 정수다. 크레이트 하나가 네이티브 커맨드와 wasm이 된다. SQLite는 `rusqlite`로 페이지 조회를 한다. 화면은 그 결과를 그린다.

## 같이 본 것

**Bevy.** ECS와 결정적 시뮬에 잘 맞는다. 조밀한 재무 UI는 아직 React가 직접적이다. 엔티티가 함수 경계를 넘으면 그때 런타임을 다시 연다. 그 전에도 시뮬 언어는 Rust다.

**Capacitor.** Tauri 모바일 플러그인이 비면 같은 Vite 앱의 대체 껍질이다. 시뮬은 그때도 wasm 또는 네이티브 커맨드로 남긴다.

**PixiJS.** 핀과 파티클이 DOM으로 부족해지면 맵 위 레이어로 얹는다. 회계를 그리지 않는다. [ADR 0004](0004-motion.md).

## 결과

- `crates/sim-core`가 기업가치와 지분가치를 소유한다. `src/sim`은 wasm 로더다.
- `crates/content-db`가 카드 페이지를 읽는다. `crates/app-commands`가 커맨드를 묶는다.
- `src-tauri`는 2.1 껍질 소스다. 이 환경에서는 링크하지 않았다.
- 릴리스 빌드의 네트워크 호출은 없다. 지도 타일도 로컬 파일이다.
- 화면 문자열은 [i18n 절차](../i18n/workflow.md)를 따른다. 로케일 파일은 한국어 하나다.
